# 工作留言板（三重龍門 × 西門）

交接班用的留言板：同事可以留「客戶預訂單 / 任務交接 / 例行工作」，
預訂單按下「確認取貨完成」就會自動扣掉 Google Sheet 裡的庫存。

- 資料庫：Google Sheet「進銷存總表－dragon2gates_bot」
  （ID `1OZsbv9IWADz0FfBxQIaDuAXXhW5U40SRzOhjIRIPIww`）
- 留言存在同一本試算表的 **「留言板」** 工作表（第一次開啟時程式會自動幫你建立）
- 庫存讀寫的是 **「Products產品」** 工作表
- 登入方式：Google 帳號登入（和 pnl-dashboard 同一個 Google Cloud 專案）

> ⚠️ 這個專案和 `pnl-dashboard` **完全獨立**：不同資料夾、不同 repo、不同網址、不同試算表。
> 唯一共用的是 Google 登入的用戶端 ID（只需要多加一個「已授權來源」，不會改到原本的設定）。

## 第一次上線（大約 15 分鐘）

### 步驟 1　建立 GitHub repo

1. 打開 https://github.com/new
2. Repository name 填 **`shop-board`**
3. 選 **Public**（GitHub Pages 免費方案只支援公開 repo；資料本身還是靠 Google 權限保護，外人打不開你的試算表）
4. 按 **Create repository**

### 步驟 2　上傳檔案

1. 在新 repo 頁面按 **uploading an existing file**
2. 把桌面 `shop-board` 資料夾裡的 **`index.html`**、**`app.js`**（其他 .md 檔要不要上傳都可以）拖進去
3. 按 **Commit changes**

### 步驟 3　開啟 GitHub Pages

1. repo 上方 **Settings** → 左邊選單 **Pages**
2. Source 選 **Deploy from a branch**
3. Branch 選 **main**、資料夾選 **/ (root)** → **Save**
4. 等 1～2 分鐘，網址就是：
   **https://willinlee20.github.io/shop-board/**

### 步驟 4　讓 Google 登入認得這個新網址 ← 最容易漏掉的一步

1. 打開 https://console.cloud.google.com/apis/credentials
2. 上方專案切到 **TOOLA MASTER DASHBOARD**
3. 點「OAuth 2.0 用戶端 ID」裡那個 `936097912364-...` 的項目
4. 在 **已授權的 JavaScript 來源** 按「新增 URI」，填入：
   ```
   https://willinlee20.github.io
   ```
   （如果這一行已經存在，就不用加，直接跳過）
5. 按 **儲存**。Google 有時要等 5 分鐘才生效，若登入失敗請稍等再試。

> 這一步只是「多加一個允許的網址」，**不會影響 pnl-dashboard**。

### 步驟 5　開權限給同事

1. 打開「進銷存總表」→ 右上角 **共用**
2. 把同事的 Google 帳號加成 **編輯者**（要能寫入才能扣庫存）
3. 如果你的 Google Cloud OAuth 同意畫面還是「測試中」狀態，
   到 https://console.cloud.google.com/apis/credentials/consent
   把同事的 Gmail 加到 **測試使用者**，否則他們登入會被拒絕。

### 步驟 6　實測一次

用手機打開網址 → 登入 → 開一張金額很小的測試預訂單 →
去試算表看 `Products產品` 的「預定專區」有沒有 +N、門市庫存有沒有 -N →
回網頁按「取消預訂」→ 看數字有沒有還原 → 沒問題就可以給同事用了。

## 之後要改東西怎麼做

在 GitHub 上直接改：repo → 點 `app.js` → 右上角鉛筆圖示 → 改完按 **Commit changes** →
等 1 分鐘，網頁重新整理（手機建議用「重新載入」）就會看到新版。

`app.js` 最上面的 `CONFIG` 區塊可以直接改的東西：

| 設定 | 說明 |
|---|---|
| `BOARD_SHEET` | 留言要寫在哪個工作表，預設 `留言板` |
| `STORES` | 門市名稱與對應的庫存欄位。`label` 是畫面顯示的名字，`col` 必須跟 `Products產品` 的欄位標題**一模一樣** |
| `SLOTS` | 取貨時間範圍選項 |
| `SOURCES` | 客戶來源選項 |
| `ROUTINES` | 例行工作的四個選項（要加第五個直接加一行） |
| `POLL_SECONDS` | 每幾秒自動抓一次新留言，預設 45 秒 |

程式是用**欄位標題**去找欄位的（不是寫死 D 欄、E 欄），
所以在 `Products產品` 中間插入新欄位不會壞掉；但**不要改欄位標題的文字**。

## 有一件事請你確認

`Products產品` 的 **「總數」** 欄（目前在 J 欄）：

- 如果它是**公式**（例如 `=D2+E2+F2+G2`）→ 最理想，程式不會去動它，它會自己跟著更新。
- 如果它是**手打的數字** → 程式會在扣庫存時，幫它重算成
  `三重店 + 西門店 + 預定專區 + 總倉數量`。

我看資料時發現有一列（酪梨倉 0.7）的總數 `9` 和各欄相加 `3+3+6=12` 對不起來，
所以這欄可能有手動改過的痕跡。**建議把整欄統一改成公式 `=D2+E2+F2+G2` 往下拉**，
這樣庫存數字最不容易出錯。如果你的「總數」公式定義跟這個不一樣，跟我說我再調程式。

## 疑難排解

| 症狀 | 原因 / 處理 |
|---|---|
| 按登入沒反應、或跳出 `redirect_uri_mismatch` / `origin` 錯誤 | 步驟 4 沒做，或還沒生效（等 5 分鐘） |
| 登入後顯示「沒有權限存取這份試算表」 | 這個 Google 帳號還沒被加入試算表的編輯者（步驟 5） |
| 顯示「找不到產品庫存工作表」 | `Products產品` 工作表被改名了，改 `CONFIG.PRODUCT_SHEET_KEYWORDS` |
| 顯示「缺少欄位：…」 | `Products產品` 的欄位標題被改過，改回來或改 `CONFIG.H` / `CONFIG.STORES` |
| 卡片上出現「重試扣庫存」 | 送出時網路斷掉，庫存還沒扣。按那顆按鈕即可（不會重複扣） |
| 同事看不到別人剛留的言 | 每 45 秒會自動更新，也可以按右上角「↻ 更新」 |
| 庫存數字怪怪的 | 試算表有版本紀錄（檔案 → 版本記錄），可以查是哪一筆動的；每張單的扣法也記在「留言板」工作表的 `庫存異動JSON` 欄 |

### 改版時我會做的事

1. `app.js` 最上面的 `APP_VERSION` 加號碼
2. `index.html` 的 `<meta name="app-version">` 和 `<script src="app.js?v=…">` 一起改成同一個號碼

`?v=` 那一段是**防止瀏覽器拿舊檔**用的。號碼一變，瀏覽器就一定會重新下載 `app.js`，
所以之後**通常不用再按 Ctrl+Shift+R**。

如果兩個檔案的版本對不起來（例如只上傳了 app.js），開啟網頁時版本號會變紅色 ⚠️
並跳出提醒，告訴你哪個檔案是舊的。
